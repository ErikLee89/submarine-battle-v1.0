# V1.0 机器码复刻

本项目独立读取 `ship_V1.0.exe`，319488 字节，32 位 PE，ImageBase `0x400000`，入口 `0x4097B2`。提取 42 个 RT_BITMAP 和 4 个 WAVE；位图由 Pillow 无损解码。`machine.js` 保存原始内存区段、入口及控制流目标的指令解码、IAT 信息。没有替换 V2.33 机器码或沿用其游戏对象字段。

| 地址 | 用途 |
|---|---|
| `0x401870` | 原版主游戏对象构造 |
| `0x402420` | OnCreate：位图、DC、背景、随机数与计时器初始化 |
| `0x403050` | 更新、碰撞、生成、计分和绘图主循环 |
| `0x4066D0` | 新游戏 |
| `0x4068B0` | 暂停 / 继续 |
| `0x406C30` | 过关与 20 关循环 |
| `0x406EC0` / `0x4072C0` | 按下 / 松开键盘 |
| `0x402F20` / `0x4072F0` | 鼠标点击 / 移动 |
| `0x407520` | 结束游戏 |
| `0x407330` | 原版排名插入 |
| `0x407CC0` | 核武器清场；拾取分支直接调用 |
| `0x4096A7` / `0x4096B4` | srand / rand |

## 可关闭的自定义扩展

`tuning.js` 默认不安装钩子。开启后分配独立的 100×56 字节友方弹药池和 100 项连击标志，只重定向已确认的友方指针读取。原混合数组中的敌方弹药保持原地址与槽位。

`0x403809`、`0x403A3C`、`0x403DCF` 的碰撞循环范围扩展至所选容量，仍运行原碰撞与计分指令。主循环原本遍历 20 项；`0x4057AF–0x405855` 的友方下沉、绘制和退出画面区段用于额外槽位，不重复运行敌方或补给逻辑。横排投弹复制原版投弹函数生成的对象并排列 X 坐标。

生命数在原新游戏返回时设置；移动速度在 `0x4065E1`、`0x4065F5` 的方向速度写入位置调整。金钟罩在原拾取赋值 `0x404DE2` 后换算所选秒数；复活在 `0x40642C` 恢复玩家存活状态时设置保护。原倒计时仍由主循环执行；暂停分支不会推进倒计时。

## 姓名与持久化

原排名对话框 `CDialog::DoModal` 在库边界 `0x4114B1` 暂停 VM。浏览器确认 GBK 名字后填写对话框 `+0x5C` 字符串，保留原寄存器和栈并继续原排名插入。随后把原 10 条排名记录保存至浏览器，用兼容的配置读取服务恢复。

V1.0 没有原版进度文件，`save.js` 实现单独标识为 `ship10-web` 的网页快照。它保存原数据区、游戏对象、VM 堆及分配信息、随机状态、自定义参数和扩展池指针；图像与系统服务重新由同一浏览器兼容层建立。

## 独立指令核对

`tools/verify_machine.py` 捕获网页兼容服务的返回值与内存写入，然后以 Unicorn 执行来源 EXE 的原始字节重放同一帧。第 1、3、7、10、16、20 关的寄存器、调用顺序和内存比较通过。该核对验证执行器和原始指令的对应关系；浏览器系统服务由两侧共享，不能据此声称每个系统 API 都与 Windows 实现完全相同。
